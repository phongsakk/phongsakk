## วิธีวัดตัวเลขที่แนะนำให้แปะบน resume (practical)

ดูหัวข้อ “วิธีวัดผลตัวเลขบน Resume” ในคำตอบแชท / ใช้ตารางด้านล่างเป็น checklist:

| หัวข้อ | วัดยังไงถ้าไม่มี KPI ทางการ | ตัวอย่างวลีบน resume |
|--------|------------------------------|----------------------|
| CLI | จับเวลา setup โปรเจกต์ 1 รอบก่อน/หลัง (หรือถามทีม) | ลดเวลาเริ่มโปรเจกต์จาก ~X ชม. เหลือ ~Y นาที |
| API gateway | ดู RPS/concurrency จาก log/APM หรือจำนวน service ที่ route ไป | รับ traffic แล้วกระจายไปยัง N API ย่อยในระบบสำนักงาน |
| Pipeline | ตัวเลขที่มีอยู่แล้ว (1M/day) + latency/error ถ้ามี | ประมวลผลเฉลี่ย ~1 ล้านรายการ/วัน |
| OCR | นับเอกสาร/สัปดาห์ หรือ % งานมือก่อน-หลัง | ลดงานอ่าน–แยกประเภทเอกสารด้วย OCR |
| Deploy | นับขั้นแมนนวล หรือเวลา release โดยประมาณ | ลดขั้นมือใน release ผ่าน GitHub Actions |

หลักสำคัญ: **ช่วงประมาณที่ยืนได้ในสัมภาษณ์ > ตัวเลขกลม ๆ ที่แต่งขึ้น**  
ถ้ายืนยันตัวเลขจริงไม่ได้ ใช้คำว่า “โดยประมาณ / roughly” และพร้อมเล่ารูปแบบการประมาณ
